## 1. デスクトップの仕事

Android は「その場で捕まえる」、デスクトップは「溜まった粒子を片付ける」。Mote は Wiki ではないので、デスクトップでも編集・整理機能は足さない。仕事は4つに絞る。

1. 読む
2. 捨てる（アーカイブ）
3. 残す（ピン）
4. 渡す（コピー、返信、将来は Wiki へ）

Capture もできるが、主役は処理（Triage）。スマホのチャット UI を横に広げると、横方向が余って一覧性が下がる。デスクトップは吹き出しのタイムラインではなく、高密度の Inbox にする。

## 2. CLI の強みをどう残すか

今 CLI が有利なのは、捕まえる速度と既存の道具との合成可能性。GUI でそれを模倣すると遅い GUI になる。CLI はそのまま残し、GUI は一覧性と処理に賭ける。

| CLI の性質 | デスクトップでの守り方 |
| --- | --- |
| 1コマンドで捕まえられる | `Mod+Shift+C` で HUD、CLI は `mote q` |
| キーボードだけで完結 | 全操作にキー。`?` で一覧。テキスト入力中は単キーを奪わない |
| パイプで繋がる | `mote q` は stdin、`mote list --json` はスクリプト向け |
| 一覧が安定 | 固定幅の時刻、コピー可能な ID、TSV/JSON 出力 |
| 起動が速い | native、前回スナップショットを即表示 |
| 状態が少ない | HUD 1枚 + CLI。トレイ常駐を前提にしない |

## 3. 画面

既定は**召喚する HUD**。コンポジタのキーで出し、`Esc` で消す。タイルの列を常時占有しない。compact は 720×900 で、リスト＋3行プレビュー。wide は 1120×900 で、リスト＋詳細を並べる。どちらも同じ HUD のモードで、wide は `Ctrl+E` で一時的に広げる。

```
┌──────────────────────────────────────────┐
│ ◌ 検索 / コマンド                 Inbox 42 │
├──────────────────────────────────────────┤
│ 11月27日（金） 今日 8件         新着 3    │
│ 12:31  明日の打ち合わせ、資料は…      ●   │
│ 11:58  長文 2,340字  購買リスト…      ●   │
│ 09:12  ↳ APIのエラー…                     │
│ ── 前回ここまで · 09:00 ──                │
│ 08:40  Moteデスクトップの一覧性…      ▌   │
│ 11月26日（木） 12件                       │
│ 23:40  Rustのnon_exhaustive…             │
├──────────────────────────────────────────┤
│ 11:58  長文 2,340字  ● 進行中            │
│ 購買リストの件、Wi-Fiルーターの…          │
│ a アーカイブ  p ピン  m 処理  Enter 開く  │
├──────────────────────────────────────────┤
│ ● 接続済み 12:31 未送信 1  j/k a m ?      │
└──────────────────────────────────────────┘
```

- 召喚: niri なら floating window、または AntiWebUI の layer-surface。`Mod+Shift+M` で一覧、`Mod+Shift+C` で Capture モード。トレイ常駐はしない。
- Overlay: 640×680 の1枚を召喚する。詳細・処理・Capture は同じ surface 内のシート、または必要なら 720×800 への拡張。別のタイル窓を作らない。`Esc` / 再召喚で閉じ、閉じたら元のウィンドウへフォーカスを戻す。
- リスト: 高密度。時刻は固定幅の左ガター、本文は2行、状態は行の中の小さな印に集約する。日付ヘッダは sticky。
- プレビュー: 選択項目の3行。`Enter` で詳細モードに移り、`Esc` でリストに戻る。詳細は別ウィンドウではなく同じ HUD の中。
- wide: リスト＋詳細の2ペイン。常駐ではなく、まとめて処理する時だけ `Ctrl+E` で広げる。
- Capture: `i` または `Mod+Shift+C`。入力欄は HUD 全体に広がり、`Ctrl+Enter` で保存、`Esc` で戻る。起動時に入力へフォーカスしない（読む優先）。
- 処理: `m` で HUD の下部に処理シートを出す。リストの背後は scrim で暗くする。
- フォーカス: 召喚時はリスト。`/` で検索、`i` で Capture。単キー操作はリストにフォーカスがある時だけ。IME 変換中は奪わない。
- 復元: 最後のビュー、スクロール、選択、HUD のサイズを覚える。狭い画面では compact を基本にし、wide は画面幅に合わせて縮める。
- 見た目: Android Mote の Ink / Lavender を基準に、wiki-gui と同じ密度のダーク。アクセントは Lavender、未送信だけ警告色。モーションは短く、完了の粒子演出は長文の完了時だけに絞る。

## 4. 一覧性

- 吹き出しを使わない。左揃え + 固定時刻 + 日付ヘッダのほうが走査が速い。チャットらしさは余白とモーションで出す。
- 行に状態を集約する: ピン、長文（長さ）、返信、未送信、アーカイブ。色だけに頼らずアイコン/ラベルを併用。
- All ではアーカイブを消さず、dim + `archived` で残す。フィルタ切替で文脈を失わない。
- 検索は現在のフィルタ内で即時。購読済みの本文を端末で絞り、ハイライトする。長文は一致箇所の前後を出す。
- ピンは並び替えない（[要件 §3.3](requirements.md)）。長文は「塊」として長さを出し、短文と混同しない。
- 新着でスクロールを飛ばさない。読んでいる位置が最新付近なら追従、そうでなければ「N件の新着」を出す。
- 「前回ここまで」ラインで、前回以降を一目でわかるようにする。最終閲覧時刻は端末ローカルに保存し、Harmion の Attribute にしない。
- 空・読込中・切断を偽らない。キャッシュは読み取り専用で出し、空の Inbox と表示しない。
- 数千件を想定してリストを仮想化する。

## 5. 操作

### 5.1 Quick Capture

- HUD は `Mod+Shift+C` で Capture モードを開く。CLI は `mote q "text"` でoutboxに預けて送信、`wl-paste | mote q` は stdin（X11 では `xclip -o`）。`mote hud` は未実装。
- niri などのコンポジタにキーバインドを1つ登録する。`Mod+Shift+C` で Capture、`Mod+Shift+M` で一覧。アプリ内グローバルホットキーやトレイは実装しない。
- `Ctrl+Enter` で保存、`Esc` で閉じる。保存はローカルジャーナルへの commit 後すぐ閉じ、ノード送信は非同期。オフラインでも「端末に預かり」として閉じる。
- 保存後に短い粒子のフィードバック。次の入力を妨げない。
- 音声入力は V1 の要件外。HUD にマイクを常設しない。このマシンの OpenAI 互換 ASR は開発用の入力アダプタとして、文字起こしを `mote q` / Capture に渡す形でのみ試す。

### 5.2 キーボード

| キー | 動作 |
| --- | --- |
| `Mod+Shift+M` | HUD を一覧モードで開く |
| `Mod+Shift+C` | HUD を Capture モードで開く |
| `j` / `k` | 次 / 前の Capture |
| `Enter` | 詳細を開く |
| `Esc` | 戻る / 閉じる / 検索解除 / 選択解除 |
| `a` | アーカイブ（取り消し可） |
| `p` | ピン |
| `m` | 処理メニュー |
| `r` | 返信 |
| `c` | コピー |
| `d` | 削除（確認） |
| `x` | 選択モード |
| `Shift+J/K` | 選択を広げる |
| `/` | 検索 |
| `1` / `2` / `3` / `4` | Inbox / 次にやる / All / Pinned |
| `Ctrl+E` | wide に広げる |
| `t` | トリアージモード |
| `i` | Capture |
| `Ctrl+L` | 長文を始める / 切り替える |
| `?` | キー一覧 |

- 単キーはリストにフォーカスがある時だけ。検索・入力・IME 変換中は奪わない。
- `a` の後は次の項目へフォーカスを移す。連続で処理できる。
- 複数選択は `x` → `j/k` → `Shift+J/K`。一括アーカイブ、ピン、長文へまとめる。
- 処理メニュー内は `n` 次にやる、`w` Wikiへ、`t` タスクへ、`d` 完了、`c` コピー。`Esc` で戻る。

### 5.3 トリアージモード

- `t` で1件ずつ表示。`A` アーカイブ、`P` ピン、`S` スキップ、`Enter` 詳細、`Esc` 終了。
- スマホのスワイプの代替。大量の Inbox を流し読みして処理する時に使う。
- 進捗（12/42）と残件数を出す。処理後の演出は控えめに。

### 5.4 IME

- 日本語入力では Enter が変換確定と衝突する。送信は `Ctrl+Enter` かボタンにし、Enter は改行に残す。
- VoxType などの外部音声入力は、HUD の標準テキスト入力欄にそのまま入力できる。Mote は ASR / マイクを持たない。
- `Esc` は IME の変換キャンセルを尊重し、アプリの閉じる操作に横取りしない。
- 検索もインクリメンタル。確定キーを要求しない。

### 5.5 長文

- Capture モードの「長文」トグル、または `Ctrl+L` で書き部屋を開く。進行中の長文は詳細の「追記」から同じ書き部屋を開く。1つの Content に追記し、明示的な「完了」で閉じる。
- `Ctrl+Enter` で区切りを追記、「完了」で `session_open=false`。入力はローカルジャーナルに先に残す。
- Capture モードの短文入力は常に新しい短文。進行中の長文への追記は詳細の「追記」から行い、同じ Content に新しい短文を混ぜない。
- 作成端末だけが追記できる（[復旧設計](recovery.md) と同じ）。他端末で進行中のセッションは読み取り専用で「他端末で進行中」と表示する。
- デスクトップは打鍵が主なので、音声前提のスレッド UI にしない。段落の集まりとして読めることを優先する。

### 5.6 処理メニュー

`m` で HUD 下部に処理シートを出す。行き先は5つ。

- 次にやる: Mote 内の軽いタスク。期日・プロジェクトは持たず、完了トグルだけ。
- Wikiへ: まず frontmatter 付き Markdown をコピーする。将来は行き先が `wiki` Kind で自分の Content を作る。Mote は `capture` を増やさない。
- タスクへ: 同様。V1 はコピー、将来はタスクアプリが自分の Kind で作る。
- 完了: アーカイブだけ。ルートしない。
- コピー: 本文だけをクリップボードへ。frontmatter は既定では付けない（行き先が決まっている Wiki へなどで付ける）。

外部へ渡した元はアーカイブし、配送後に不要なら明示的に削除する。コピーは行き先が自分の Kind で作り、`mote_id` を来歴に残す。Mote が `capture,wiki` のコピーを作らない。

## 6. 状態と信頼性

- HUD の上端に接続と同期を、下端に未送信・最終同期・要確認を出す。未送信は行にも印を付ける。
- 楽観更新し、ローカルジャーナルに commit してから表示する。ノードが拒否したら戻す。
- オフライン時は最後のスナップショットを読み取り専用で表示。操作はコピー以外を無効化し、空の Inbox と混同しない。
- 自動再送はしない（[復旧設計](recovery.md)）。再送は明示操作。結果不明は「要確認」に集める。
- 認可は `capture` Kind だけを持つ別アプリケーション（`mote`）として要求する。既存の `harmion` CLI の owner 権限を流用しない。CLI は `mote connect` で所有者承認済みのcapture-only credentialを取得・保存し、期限前にOAuth refreshする。`--owner` は明示的なローカル管理者フォールバック。
- 削除は確認画面。アーカイブは即時 + undo。ピンは即時。
- 返信は `reply_to` を保存し、一覧では1行の引用、詳細では引用ブロックを本文の上に出す。返信先が消えても返信は残す。

## 7. CLI と共有コア

```
mote-core  ── mote (CLI)
           └─ mote-hud (GUI)
```

- `mote-core`: capture の投影、属性、フィルタ、並び順、保存 field。UI・接続・ジャーナルはまだ持たない。
- `mote`: `connect`, `auth`, `q`, `list`, `show`, `search`, `archive`, `unarchive`, `pin`, `unpin`, `pending`, `retry`, `forget`。`--json` / `--tsv`。HUD 用の `hud` と `status` は未実装。
- `mote-hud`: AntiWebUI（wiki-gui と同じ）を第一候補。Wayland の浮動ウィンドウ／layer-surface。トレイなし。HUD はまだ設計のみ。
- CLI は HUD と並ぶ正式な面。HUD の画面やキーを CLI に移植するのではなく、`q` / `list` / `show` / `search` / `archive` / `pin` の操作語彙を共有する。音声は CLI に入れない。
- CLI は `q` の送信前にローカルoutbox（`~/.local/state/mote`、0700/0600）へ保存し、`pending` / `retry` で回収する。HUD を実装するときは同じoutbox形式を共有し、ロックを追加して二重送信を防ぐ。現行CLIは固定request IDによる冪等再送で重複を避ける。`mote-core` 自体はまだジャーナルを持たない。
- ノードが正本。独自同期は持たない。購読は `harmion_client` の `subscribe`、キャッシュは読み取り専用。

例:

```sh
mote list                 # Inbox
mote list --all --json
mote show <id>
mote archive <id>...
mote q "あとで調べる"      # outboxに預けて送る
wl-paste | mote q
# HUD は将来 mote hud（未実装）
```

## 8. V1 の範囲

- 読み取り、フィルタ、検索、詳細、アーカイブ/ピン、複数選択、返信、コピー
- 短文 Capture、Quick Capture、長文（テキスト）
- HUD（compact / wide）、処理シート、前回位置
- キャッシュ、未送信、要確認、切断表示
- 音声、LLM 整形、派生 Content、Wiki/task への自動搬出、編集、タグ/フォルダは V1 外
- まず薄い `mote` CLI を作って日常で使い、操作語彙を固めてから GUI に移す。GUI と同時でもよい。

非目標:

- ノートエディタにしない。既存 Capture を編集しない。
- Wiki の代替にしない。タグ・フォルダ・階層を作らない。
- 独自の同期を持たない。ノードの権限と競合処理を尊重する。

## 9. 決めること

1. 並び順: デスクトップは新しい順を既定にするか、スマホと同じ古い順か。
2. 長文: スレッド追記か、エディタ風の1画面か。
3. V1 に音声を入れるか（テキスト優先を推奨）。
4. 実装: AntiWebUI の layer-surface HUD か、GPUI（ltrait-ui-lelke）か、TUI か。まず AntiWebUI の HUD spike を通す。
5. 処理のコピー方式: 行き先が自分の Kind で作る（既定候補）か、同じ Content を引き継ぐか。
6. 配布名と認可: `mote` アプリとして別途承認するか、既存の native プロファイルに同居させるか。

## 10. UX の受入チェック

- 他アプリからキー1つで HUD が開き、`Ctrl+Enter` で端末保存され、ノード未接続でも消えない。
- HUD は 640〜720 幅でタイルを崩さず、`Esc` で閉じると元のウィンドウにフォーカスが戻る。
- VoxType で Capture に入力でき、Mote 側にマイク / ASR がない。
- `Ctrl+E` で wide に広げ、リスト＋詳細で読める。元の幅に戻せる。
- ノード停止中も前回一覧が読め、操作不可の理由が表示される。
- 1,000件でもスクロール・検索が実用速度。新着で読書位置が飛ばない。
- Inbox / 次にやる / All / Pinned / 検索を往復しても、スクロール・選択・検索語が戻る。
- 日本語 IME の変換確定で送信されない。
- `a` の連続処理でフォーカスが次へ移り、undo できる。
- `m` の処理シートで次にやる／Wikiへ／タスクへ／完了／コピーを選べる。
- 長文セッションをアプリ kill 後も再開でき、二重追記しない。他端末からは読み取り専用。
- キーボードだけで全操作できる。
