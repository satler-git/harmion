# Mote — テキスト Capture の実装と確認

[要件 v0.2](mote-requirements.md) の短文・長文テキスト Capture を実装する。Mote はノードの `:app` とは別 APK（`android/mote`、Gradle パス `:mote`、applicationId `dev.satler.mote`、Kotlin namespace `org.harmion.mote`）。公開ホスト・DNS・外部 API は不要で、Harmion の宛先をこのドメインに固定しない。

## 動作と責務

- **UI:** [Drift のダーク Material 3 Expressive](../android/mote/src/main/java/org/harmion/mote/MoteTheme.kt) を標準にする。ホームの Inbox は日付で区切った時系列、Archived は日付見出しを置かないアーカイブ順（最近が下）の一覧で、短文は右寄せの吹き出し、完了した長文は横幅いっぱいのプレビューに本文を最大 3 行表示する。短文は本文の幅に合わせて最大 97% まで広がり、既定 7 行まで表示する。各メッセージの時刻は吹き出しの外の左側に置き、メッセージの高さを節約する。時刻の間隔が空いた箇所は余白を増やす。7 行を超える短文はタップでその場に全文を展開し、折りたたみボタンで戻せる。下部に長文の再開、Inbox / Archived のアイコン切り替え、ピン留めフィルター、返信の引用、入力をまとめる。上下のバーは後ろの一覧をぼかして重ね（Android 12 以上。それ未満は半透明のスクリム）、キーボード表示中はフィルター類を畳む。ヘッダーは左上に接続・同期の状態、右上に即時同期と設定を置き、一覧をスクロールすると隠れる。長文画面は本文を全幅で表示し、共有リンクには同じテキストの下書きとして補足を加えられる。拡大ボタンで長文を始めると、入力中の短文は長文の下書きとして引き継ぐ。アーカイブ操作時は入力フォーカスを閉じる。起動時は入力欄にフォーカスせず、閲覧を優先する（書くときは入力欄をタップする）。
- **操作:** 省略されていない短文のタップは詳細、省略された短文のタップはその場での展開／折りたたみ。長文のタップは詳細。長押しで返信・詳細・選択・ピン留め・コピー・OS 共有・アーカイブ・削除にアクセスする。右スワイプは約 32% の距離を目安にアーカイブ／解除、左スワイプは返信。確定後は一覧へ先に反映し、ノードが拒否したら戻す。Snackbar で取り消せる。削除は別の確認画面からだけ実行し、進行中の長文はセッションを閉じてから本文を削除する。
- **ViewModel:** 下書き・保留・承認・購読・操作結果・返信先・同期状態を UI に渡す。最後の完全なスナップショットを保持し、再接続中も一覧を読み取り専用で表示する。書き込みは一度に一操作。
- **CaptureRepository:** ノードを正本とする。`capture` Kind の read / write だけを要求し、Android SDK の署名検証済み Binder と証明書ピン付き HTTPS で接続する。独自同期や Wiki 操作は持たない。

## Harmion に保存する形

短文送信 1 回 = `capture` Kind の Content 1 件。Body は普通のテキスト。属性は `capture` 名前空間に保存する。内容に別の Kind が共存できるというノードの設計は変更しない。

| key | 値 | 規約 |
|---|---|---|
| `created_at_micros` | UTC epoch µs の整数 | 作成時に一度設定。日時なしの Content は先頭に置き、同順位は Content ID 順。 |
| `archived` | bool | 不在は false。Inbox は false のみ、Archived は true のみ。 |
| `archived_at_micros` | UTC epoch µs の整数 | アーカイブ時に `archived` と同じ edit で設定し、解除時に削除する。不在の古いアーカイブは Archived の先頭に作成順で置く。 |
| `pinned` | bool | 不在は false。Inbox / Archived と独立した絞り込み。 |
| `session_open` | bool | 長文の初回追記で true、明示完了で false。短文では不在。 |
| `reply_to` | string | 返信先の Content ID。不在は通常の短文。返信先が削除されても連鎖削除しない。 |

長文セッションは最初の追記で Content 1 件を作成し、その後は同じ ID の本文に空行を挟んで追記する。作成端末の Mote がローカルに長文セッション 1 件を保持し、ホームへ戻る操作やアプリ終了では完了しない。他の端末では本文を閲覧できるが、そのセッションへ追記はできない。進行中の Content を消す操作は、セッションを閉じてから本文を削除する二段階だけを許す。下書きカードの長押しからも同じ操作を実行できる。未送信のローカル下書きは失われるため、確認画面で明示する。

複数の短文を選択して長文へ移すと、選択順に空行で区切って一つの長文本文へ追記し、元の短文は Harmion から削除する。これは短文を圧縮して長文へ畳む操作であり、アーカイブによる重複は残さない。

`derived_from` は LLM 整形の導入時に定義する。音声認識中・LLM 実行中などの一時状態は Content に保存しない。

## 接続・書き込みの境界

1. 起動時はアプリ専用領域の最終スナップショット（編集トークンを含まない読み取り専用キャッシュ）を先に表示し、`SnapshotEnd` を受けたら差し替える。キャッシュはバックアップ対象外で、サイズ上限を超える場合は保存しない。完全なスナップショットを一度表示した後は、再接続・一時的な通信断・`ResetRequired` でも最後の一覧を保持し、読み取り専用で表示を続ける。操作確認は Ready に戻るまで無効にし、詳細は次のスナップショットで更新する。1 回の購読で 3 回までリセットを許容する。一時的な通信断では一覧購読だけを最大 2 回再試行し、書き込みは再送しない。復帰できない場合は手動再接続にする。手動再接続は古い購読の終了を無期限に待たず、20秒以内に最初のスナップショットが来なければ未接続として扱う。現行 SDK は全本文を受け取るため、大規模 Inbox のメモリ負荷は未評価。
2. 下書きはバックアップ対象外のアプリ専用領域へ保存する。短文送信時は固定 ID と認可主体付きの create 要求を送信前に永続化し、保存の応答を受けるまで下書きを消さない。再送は明示操作だけ。`view: null` でもローカル書き込みに成功し得る。端末間同期は待たない。[失敗時の詳細](mote-recovery.md)と[保存契約](../contracts/app-save-v1.md)を参照。
3. ピン留めは現在の可視性と属性値を `get` で再確認し、該当属性だけ変更する。アーカイブは `archived` と `archived_at_micros` をまとめて変更する。削除は再確認後に、確認画面の編集トークンを使用する。別 Kind が見える Capture や可視競合のある Capture は削除しない。`get` と書き込みの間に競合し得るため、条件付き delete と同等ではない。Phase 1 では派生を生成せず、連鎖削除もしない。
4. 承認待ちの接続要求（接続 ID・secret・PKCE verifier）はアプリ専用領域に暗号化保存し、プロセス再起動やキャンセル後は同じ要求を再開する。ノード側で承認済みなら承認 UI を出さずに完了する。完了済みで資格情報を引き継げない場合だけ、新しい承認を求める。接続要求と承認トークンの寿命は15分、SDKの待ちは12分とし、期限直後は最終確認する。ノードの承認画面には、既存の認可があっても新しい接続要求には「許可」が必要であることを明記する。
5. ヘッダーの同期ボタンは SDK の `requestSync` でノードに早期の同期パスを要求する。ノード側のポリシー（Wi-Fi、従量制、電池など）は尊重され、60 秒/UID の要求制限がある。完全にポリシーを無視する手動同期はノードの所有者 UI だけが行える。同期中はボタンを回転し、最終成功時刻・ポリシー・失敗理由は設定に表示する。

## 起動・確認

リポジトリのルートから（他の Android モジュールと同じツールチェーン）:

```sh
nix develop .#android
gradle -p android :mote:assembleDebug :mote:testDebugUnitTest
# Android 10 以降の検証端末またはエミュレータ
adb install -r android/mote/build/outputs/apk/debug/mote-debug.apk
adb shell am start -n dev.satler.mote/org.harmion.mote.MainActivity
```

対応する署名のノードを導入する。JNI の生成は [build-rust.sh](../android/scripts/build-rust.sh)、ノードの証明書ピンは [署名手順](android-release.md) を参照。動作確認は、`capture` 限定の承認 → 短文を保存 → 再起動して表示 → アーカイブ／取り消し → 確認付き削除の順が分かりやすい。

長文の確認は、追記 → 次の下書きを入力 → アプリを終了・再起動 → 「長文を再開」 → 明示完了、の順で行う。再起動後は同じ本文と下書きが復元される。「完了」は残りの下書きも追記して閉じ、保存の照合が終わったら Inbox に戻って短い粒子のフィードバックを表示する。Harmion への保存結果が不明なら、本文／状態が一致するときだけ利用者が採用できる。照合は追記や完了を再送しない。詳しくは [復旧設計](mote-recovery.md#2-長文追記の直列化と終了境界) を参照。

アーカイブの確認は、2件を順にアーカイブ → Archived で後にアーカイブした方が下に来ること → 解除して Inbox に戻ること → 取り消すと元の Archived の位置に戻ること、の順で行う。

返信の確認は、左スワイプ → 引用を確認 → 送信 → 返信先の削除後に「元のメモは見つかりません」が残ること、の順で行う。複数選択の確認は、長押し → 選択 → 2件以上を選ぶ → 長文へ → 元の短文が消え、長文に空行区切りで残ること、の順で行う。下書き削除は、ホーム下部の長文カードを長押し → 確認 → 一覧と長文画面から消えることを確認する。同期ボタンは、押下中に回転し、設定に最終成功時刻と失敗理由が出ることを確認する。IME を閉じた後にカーソルが点滅しないこと、上下バーの後ろのメッセージがぼけて見えることも実機で確認する。

ほかのアプリからテキスト／URL を OS 共有すると、Mote は専用の短文入力画面だけを開く。共有内容に補足を足して保存するか、キャンセルして呼び出し元に戻れる。共有の下書きと保留はホームの下書きとは別に保存する。

音声入力は [Phase 3 の候補比較とデバッグ版の録音検証](mote-phase3.md) を参照。

**未実装:** 音声認識、LLM 整形（長押しメニューに置く予定）、短文入力3行以上でのボタン移動、CLI。未実装の操作ボタンは表示しない。
