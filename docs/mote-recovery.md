# Mote — 失敗時の振る舞い

[要件 §§2, 5–7, 9](mote-requirements.md) のうち、後から直すと記録を失い得る境界だけを扱う。短文・長文テキストの実装は [実装と確認](mote-design.md) と本書 §§1–2 を参照。複数入力のキュー、音声、LLM の記述は後続の設計案で、Harmion の契約は変更しない。

## 1. 送信ボタンを押した事実と、ノードが保存した事実を分ける

Mote のアプリ専用領域に小さな永続キューを置く。これは同期する別 DB ではなく、転送前／結果不明の入力の復旧用。UI 上は「端末に預かり」「Harmion に保存」「要確認」を区別する。

- 入力確定時、下書き版・本文・対象・連番をキューに移す操作を 1 ローカルトランザクションにする。完了する前は入力を消さない。同じ下書き版の二重送信は禁止し、送信後に書いた次の下書きを古い応答で消さない。
- ノードに送る**前に** `cluster/node` と認可先アプリの同一性、32 byte の `request_id` / `content_id`、全 fields（作成時刻を含む）、編集時の basis トークンを含む不変な save 要求を保存する。認証用 access/refresh token をコピーしない。ノードや認可先の同一性を照合できない再接続では送らない。
- `queued`（未送信）→ `in_flight`（送った可能性あり）を durable にしてから I/O → 成功時に `update_id` と `accepted` を記録。そこで初めて「Harmion に保存」。`view:null` は未保存を意味しない。確定前の入力保護と次の本文を組み立てるための照合は別。長文は確認が済むまで入力断片を残す。
- 再起動後の `in_flight` は結果不明。**新 ID での自動再作成、本文末尾への再追記、最新トークンへの自動差し替えは禁止**。create は固定 ID で同一要求を再送可能（ID 使用済みでも別 Content は作らない）。edit/delete は receipt が回収され得るので、不明時には自動再送しない。`get` で現在の通常値・競合・可視性を確かめ、確認不能なら入力／計画を保持して止める。同じ文字列が見えただけでは元の操作の receipt の証明にならない。「現在値を採用」または明示的な新規保存をユーザーが選ぶ。

根拠：[App API §§2–3](app-api.md)、[アプリ別 receipt・固定 basis](../contracts/app-save-v1.md)。30 日以内でも容量 GC があり、`request_id` だけでは永久の exactly-once にできない。固定 ID の create 再送でも receipt 回収後の既存 ID は 400 になり、権限外／削除済みなら `get` も 404 になり得る。いずれも「最初から未保存」の証明ではない。

**Phase 1 の実装範囲:**

- 複数の保留を扱うキューではなく、[単一の下書き／保留ジャーナル](../android/mote/src/main/java/org/harmion/mote/CaptureJournal.kt)を使用する。端末内で書き込みを一件ずつ直列化し、送信前に下書きと固定 create 要求を原子的に保存する。再起動後は保留として表示するだけで自動送信しない。受理を確認できた後の消去書き込みが失敗した場合も保留が残り、同一要求で再照会できる。
- [SDK の認可主体付き save](../android/sdk/src/main/java/org/harmion/sdk/Session.kt) では `(clusterId, nodeId, clientId)` を現行の資格情報と照合し、同一セッションの認可変更・送信を直列化する。401 リトライも照合する。認可先が異なる場合は再送不可。保留は確認操作で解除でき、本文は下書きとして残すが、次の送信は新規作成であることを明示する。アーカイブ・ピン留め・削除の結果が不明な場合は自動リトライしない。

## 2. 長文追記の直列化と終了境界

長文は初回の確定入力で Content を作成（`session_open=true`）。初回以前の空セッションは端末内だけ。追記はノードの append API ではなく **全文 body の edit**。入力順に同一 Content 一件ずつ送る。元本文＋区切り `\n\n`＋確定入力と、その元を読んだトークンを対で固定する。

- **Open:** 画面遷移や認識の停止では閉じない。テキスト送信／音声 final ごとにローカル連番を採番。起動時にキューを読み、同じセッションに再接続。初期版で追記できるのは作成端末のみ（ローカルに対応表がない他端末は閲覧のみ）。これは分散ロックではない。
- **Finishing:** 明示的な完了で新規入力を閉じ、認識中なら stop と final の取り込みを待つ。stop 境界（録音 ID・カットしたサンプル位置）を記録し、そこまでの final／未認識区間が決まってから、最後の受付連番と期待する全文ハッシュを永続化する。そこまでの全件が保存・照合されてから `session_open=false` を単独 edit。処理中に離脱しても再開時に同じ境界から続行。保存不能／未回収音声があれば保留とし、復旧・退避または該当区間の明示破棄を選べるようにする。入力も音声もないセッションは端末内で閉じ、空 Content や整形ジョブは作らない。
- **Closed:** close の受理後、receipt の view を使い回さず `get` で期待する全文ハッシュ・`session_open=false`・`capture` 所属・関係する公開競合と削除競合の不在をまとめて照合する。外部が本文だけを変更した後に close 属性だけ受理される場合も、誤って自動整形を始めない。照合済み終了と、設定が有効ならその受付連番に対する一意な整形予約を同じ端末内トランザクションにし、完了表示する。音声 stop 単独ではこの遷移は起きない。
- **要確認:** 追記前／保存後に `get` し、期待した本文・open 状態・Kind と本文／状態の競合、`deletion_conflict` を確認。不一致／不可視／トークン失効／上限超過なら後続を止め、未確認断片を取り出せるようにする。外部の変更を自動マージしない。`get`→`edit` は CAS でなく、後から届く同期競合も排除できない。Harmion の履歴を変更して競合を隠さない。1 MiB の record／要求上限は文字数でなく符号化後に効く。超過時は別 Content に黙って分割せず、元を残して断片の退避を案内する。

**Phase 2 の実装範囲（テキストのみ）:** [長文ジャーナル](../android/mote/src/main/java/org/harmion/mote/LongCaptureJournal.kt)に作成端末のセッション 1 件、下書きと保留操作 1 件を記録する。初回追記の前までは端末内だけ。追記・完了は、認可主体と元の本文を確認し、固定要求を端末に保存してから送る。受理後も新しい `get` で本文と `session_open`、可視競合を照合するまで下書き／保留は残す。受理が不明の場合は create を含めて自動再送しない。利用者が「一致時に採用」を選ぶと現在値を照合するだけで、受理記録の代用にはしない。不一致や不可視の場合は停止し、本文のコピーで退避できる。確認付きの「端末の記録を破棄」は Harmion を変更しないため、ノード上のセッションが進行中のまま残る場合がある。複数入力のキュー・音声停止境界・整形予約は未実装。

## 3. 録音の寿命と復旧できる範囲

画面からは開始・停止だけを指示する。マイク権限を得た可視 Activity から microphone 型 Foreground Service を開始し、録音中の通知に stop を出す。ロック・画面遷移で Activity が消えても、Service が音声入力を所有する。通知拒否などで要件どおりの状態表示・通知停止を提供できない場合は開始しない。OS の強制停止後に黙ってマイクを再開しない。

- 音声ストリームは一箇所で取得し、端末内の分割録音と交換可能な ASR に渡す。エンジンが自身でしかマイクを開けない構成は二重取得を前提にせず、元音声保持と両立するかを先に実機検証する。partial は表示だけ。録音側が付番したサンプル範囲を使い、final の区間キー `(recording_id, 開始, 終了)` の登録と、短文の下書き版／長文の追記キュー行の作成を**同じローカルトランザクション**にする。音声保護はその commit 前には解除せず、commit 後も未復旧部分が残るファイルは保護する。再配送された同一区間は二重反映せず、重複する別区間や時刻を対応付けられない final は自動追記せず確認に回す。無音や ASR の発話終了はユーザーの停止でない。クラウド ASR は音声・宛先を指定した明示許可がある場合だけ。ローカル ASR 不可時に無断で切り替えない。
- 一時ファイルに書き、読み戻せる単位で閉じてから区間を索引に登録する。ファイルと DB は同時 commit ではない。起動時に孤立ファイル／欠損区間／終端が不完全なファイルを照合し、復元できた区間だけを提示。復元不能な末尾まで確定したとは表示しない。
- 通知 stop は同じ録音 ID に対して冪等。新規音声を遮断して受領済み final を drain。ASR が戻らない時は音声区間を「未認識」に残し、UI で再入力・確認できるようにする。低容量時は過去の未復旧音声を犠牲にせず新規録音を停止し通知する。完了済み音声のみ期限削除、保護対象の破棄は本人確認操作。音声・復旧用本文をバックアップ、同期、ログ、LLM 送信に含めない。

## 4. 整形・再整形・削除は複数 Content のトランザクションではない

1. **計画:** 閉じた原文の ID と `SHA-256(UTF-8 の原文そのまま)` を固定する。クラウド利用は既定 off。予約時の許可を持ち越さず、外部への送信・再試行の**直前**に宛先別の現行許可と原文の可視性・完了状態・ハッシュ・競合の有無を再確認する。確認不能または失効なら送信しない。既に送った本文は許可撤回でも取り戻せない。LLM の出力は本文の配列だけを受け付け、空・不正・上限超過なら書かない。ID・Kind・属性・削除命令を LLM に選ばせない。
2. **追加:** 検証した各本文、各子の固定 ID と create 要求、ジョブ ID を端末に記録してからノードへ送る。子の Kind は `capture` のみ。参照属性には `derived_from`、来歴には source hash、job ID を持たせる。子の書込前・全件保存後に原文を再取得。変更・競合・不可視ならその世代を「旧本文由来／中断」として扱い、既に作った子は消さず、元も旧世代も残す。別端末には途中の子が見え得る。これは全件公開の原子性ではない。再開時は計画を使い、LLM をもう一度呼んで別出力を混ぜない。
3. **置換／連鎖削除:** 参照は所有権の証拠ではない。初期の管理対象候補は **この端末の生成記録に ID があり**、現在の親参照・job・生成内容が一致し、通常 Kind が `capture` のみで、可視競合のない子。別端末作成／他 Kind 併存／来歴不明は自動削除から除外し、確認画面で対象外として示す。新世代全件の受理と照合前は旧世代を一件も消さない。元の削除確認より先に、その元 ID の端末内ジョブに永続的な書込停止フラグを立てる。新規ジョブ・子送信の予約と停止フラグを同じトランザクション境界で直列化する。送信予約済みの子は受理／未送信を照合し、不明が残れば元を消さない。その後、固定した対象 ID と本文抜粋を確認し、子から処理して元は最後。中止時だけ本人操作で停止を解除する。これは別端末の生成を止める仕組みではない。途中失敗時はどこまで受理されたかを表示し、対象を再検索して勝手に追加しない。派生だけの削除は親をたどらない。
4. **保証の限界:** 通常の `get` 後にも別端末で本文や Kind が変わり得る。可視 Kind が一つでも非公開の Kind 競合までは証明できない。現行の固定 basis delete を条件付き delete とみなさない。従ってバックグラウンドの自動破壊的 cleanup は解禁しない。Phase 4 はまず「保持・追加」。厳密な置換・連鎖削除を有効にする前に、ノード側で対象条件・basis を保存時に検査できるか、または利用者が明示的に引き受ける競合時の手動操作の範囲を別途決める。元の自動アーカイブも既定 off。

## 実装の受入条件（未実施）

| 割り込みを入れる場所 | 観測する結果 |
|---|---|
| 送信確定直後、save 前、ノード commit 後に応答喪失、receipt 回収後の復帰 | 入力消失・別 ID の自動作成なし。受理不明は成功表示しない。再認可先が変われば送らない。 |
| 同じノードで A→B に再認可、SDK の資格情報保存直後に kill／401 再試行 | A のキューを B の資格情報で送らない。`applicationId` が同一でも停止する。 |
| 購読中に権限縮小→reset→次の購読失敗、または上限で reset を反復 | 旧一覧・詳細を残さず、失敗を空 Inbox と表示しない。無限再購読しない。 |
| 2 回の final と完了操作が競合、続いて別端末から body 編集 | 受付済みの区間を重複なく復元し、競合を無視して全文置換・整形しない。 |
| ロック／再生成／通知 stop／強制終了／容量枯渇 | マイク使用中が分かり stop できる。復帰後は保存済み音声・転記済み区間・欠損を区別し、自動再録音しない。 |
| 派生生成の各件の直前直後で kill、原文の同時変更、別 Kind 追加 | 原文・旧世代が残る。同じ子を再生成しない。不確かな子を消さない。 |
| 最終追記照合後に別端末で本文を変更し、close 属性だけ成功 | 受理済みでも照合は「要確認」。完了表示・自動整形なし。 |
| ASR の区間確定トランザクションの直前／直後で kill | 短文・長文とも 1 回だけ反映されるか、音声が未認識として残る。 |
| クラウド処理を予約後に許可撤回または原文変更 | テスト用宛先で、撤回後の新規外部送信／旧本文の再送が 0 件。 |
| 子の create 応答喪失 → 元の削除を要求 → 再起動 | 不明な子がある間は元を削除せず、旧ジョブからの新規送信もない。 |

**長時間稼働の判定:** 約 512 byte の final を 1,000 回逐次追記すると、最終本文は約 0.5 MiB でも送信する全文の累計は約 245 MiB になる。対象端末・ノード・ASR の組合せで画面消灯から通知停止、復帰、最終本文照合まで測る。録音時間、確定頻度、許容キュー遅延・残容量を試験前に定め、未達なら対応時間を明示するか、ローカル確定は毎回行った上で有界な時間・サイズで連続断片をまとめて送る。録音単体の成功を長文 Capture の合格としない。
