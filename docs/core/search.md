# Harmion の標準検索（草案）

更新日 2026-11-21

Wiki やメモなど、複数のアプリが保存した Content を Harmion の標準機能で探せるようにする。覚えている語での全文検索と、内容だけを覚えているときのベクトル検索を、同じ検索欄から使えるようにする。本書は設計案であり、現行の API 契約は [Query と Subscribe の仕様](requirements.md#61-読み出しと通知)を参照。

## Query と Search

`Query` の型付き条件で対象を厳密に絞り、`Search` で検索文に対する関連度順に並べる。所有者向けの横断検索も、Wiki 内検索も同じ `Search` を呼ぶ。Wiki 内で探すときは `kind = wiki` を指定し、必要に応じて最終編集時刻などを組み合わせる。

| 項目 | 草案 |
|---|---|
| 入力 | 検索文 `text`、任意の `filter`（既存の Query 条件 AST）、取得件数 |
| 結果 | Content ID、表示に使うタイトル（あれば）、関連する本文の抜粋、不透明なページカーソル |
| 検索対象 | 接続先ノードの通常表示。本文と、アプリがタイトルやタグとして検索対象に指定したテキスト属性 |
| 並び順 | 関連度順。同順位では Content ID で順序を決める |

初回の検索で結果の順位と表示内容のスナップショットを固定し、ページ送信時にも現在の `Read` 権限を検査する。検索は既存の `Read<Filter>` を使い、候補の選択にも権限と `filter` の両方を適用する。上位候補を選んでから絞ると、対象範囲にある関連文書を取りこぼすため、絞り込みは候補取得の一部とする。

## 全文検索とベクトル検索

全文検索は、タイトルや本文の語句、部分一致、エラーコードや識別子を拾う。日本語の短語、日英混在、全角・半角などの表記ゆれは初期の検証対象とする。ネイティブ SQLite では FTS5 が候補になる。trigram の全文検索では `同期` のような2文字の語を拾えないため、短語向けの検索方法も検証する。 [SQLite FTS5 の trigram tokenizer](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

ベクトル検索では、本文を段落などのまとまりに分け、タイトルがあれば添えて埋め込む。検索文を同じモデルで埋め込み、ベクトルが近い段落を候補にする。たとえば「前に請求を二重に処理したとき、どう直したっけ」という検索で、「支払い処理の冪等性キーを追加した」と書かれたメモが上位に出ることを目指す。

双方の候補を Content ID でまとめ、タイトル・識別子・フレーズの強い一致が埋もれないよう順位を付ける。長い文書から複数の段落が見つかった場合も、検索結果は Content ごとに一件にまとめ、関連する箇所を抜粋として返す。順位の合成方法と重みは試作で比較する。

## ノードごとの索引

- 全文索引と埋め込み索引は、各ノードが通常表示から再構築できる派生データとして管理する。埋め込みは Content の同期・エクスポート形式の対象外とする。
- 本文や対象属性の変更は全文索引に反映し、埋め込みはバックグラウンドで差分を再計算する。再計算中の Content は現行の通常表示で全文検索できる。変更前の段落に由来する古いベクトルは新規検索の候補から外す。
- 埋め込みは、対象テキストと、モデル・前処理・分割方法の版に結び付ける。計算中に通常表示が変わった場合は、入力が現在の索引対象と一致する結果だけを採用する。
- 標準構成では接続先ノード内で本文と検索文を処理する。モデル未導入や索引構築中でも全文検索を返し、意味検索の利用状態を呼び出し元が確認できるようにする。

## ネイティブ版の試作

小型の多言語モデルを端末上で動かし、権限と Query 条件で絞った段落のベクトルを総当たりで比較する。`multilingual-e5-small` を比較の出発点とする。まず全文検索単体・ベクトル検索単体・両者の併用を、同じ検索例で比べる。 [Multilingual E5 のモデルカード](https://huggingface.co/intfloat/multilingual-e5-small)

- 日本語の短語、固有名詞、識別子、表記ゆれ、言い換え、日本語から英語のメモを探す例を用意し、期待する Content が上位5件に入る割合を見る。
- 端末での検索応答時間、初回構築と差分更新の時間、索引サイズを測る。総当たりの応答時間が実用上の制約になった段階で近似最近傍索引を比較する。
- 編集・削除・同期で通常表示や `Read` 権限が変わるケースを検証する。再索引の途中やページ送りでも、権限外の本文や抜粋が返らないことを確認する。

モデルの標準採用、属性を検索対象に指定する形式、順位付け、索引状態の応答形式、Cloudflare ノードの対応範囲は試作後に決める。
